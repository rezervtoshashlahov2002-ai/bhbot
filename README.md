# Telegram-бот: рабочие процессы, чек-листы, финансовый учёт и статистика

Бот на **Python 3.12+ / aiogram 3.x** с базой данных **SQLite**. Реализует
защищённый паролем доступ, пошаговый процесс (чек-лист), финансовый учёт,
список ресурсов, статистику и админ-панель. Данные каждого пользователя
полностью изолированы. Готов к деплою на **Railway**.

## Возможности

- **Авторизация по паролю.** Неавторизованный пользователь отправляет пароль
  сообщением. Несколько администраторов. Бан/разбан, выдача/отзыв доступа.
- **/work** — главное меню (inline-кнопки): процесс, финансы, ресурсы, статистика.
- **/circle** — интерактивный пошаговый процесс (13 шагов по умолчанию,
  настраивается в `process_steps.py`).
- **/money** — баланс (увеличить / уменьшить / задать вручную) и история операций.
- **/proxy** — список ресурсов: добавление, удаление, просмотр, нумерация,
  выбор по номеру.
- **/stats** — завершённые процессы, суммарная прибыль/убыток, число нажатий
  «Табла», среднее время прохождения процесса.
- **/admin** — админ-панель (список и статистика пользователей, управление
  доступом и админами, смена пароля).

## Переменные окружения

| Переменная         | Назначение                                                        |
|--------------------|-------------------------------------------------------------------|
| `BOT_TOKEN`        | Токен бота от @BotFather (**обязательно**).                       |
| `INITIAL_ADMIN_ID` | Telegram ID первого администратора — авторизуется автоматически.  |
| `DEFAULT_PASSWORD` | Пароль доступа при первом запуске (по умолчанию `changeme`).      |
| `DATABASE_PATH`    | Путь к файлу БД (по умолчанию `bot.db`).                          |

Скопируйте `.env.example` в `.env` и заполните значения. Свой ID можно узнать
у бота `@userinfobot`. Первый администратор задаётся через `INITIAL_ADMIN_ID`,
далее новых админов можно добавлять через `/admin`.

## Локальный запуск

```bash
pip install -r requirements.txt
cp .env.example .env        # затем впишите BOT_TOKEN и INITIAL_ADMIN_ID
python bot.py
```

БД создаётся автоматически при первом запуске. После перезапуска данные
сохраняются (файл `bot.db`).

## Деплой на Railway

1. Залейте проект в репозиторий GitHub и создайте проект на Railway из этого репозитория.
2. В **Variables** задайте `BOT_TOKEN`, `INITIAL_ADMIN_ID` (и при желании
   `DEFAULT_PASSWORD`).
3. **Важно — сохранность данных.** Файловая система Railway эфемерна: без
   постоянного тома SQLite-файл сбрасывается при каждом редеплое. Подключите
   **Volume**, смонтируйте его (например, в `/data`) и задайте переменную:
   ```
   DATABASE_PATH=/data/bot.db
   ```
   Тогда база переживёт перезапуски и обновления.
4. Запуск задан в `Procfile` (`worker: python bot.py`) и `railway.json`.

> Переход на PostgreSQL при необходимости делается заменой слоя в `db.py`;
> остальной код работает через его функции и не привязан к SQLite напрямую.

## Как изменить шаги процесса

Откройте `process_steps.py` и отредактируйте список `STEPS`. Каждый шаг — это
словарь с полями `title`, `text`, опционально `input` (`"resource"`,
`"result"`, `"profit"`), `tabla` (кнопка «Табла») и `final` (завершение
процесса). Нумерация «Шаг N/Total» проставляется автоматически по позиции в
списке, поэтому шаги можно свободно добавлять, удалять и переставлять.

Поведение ввода: на шагах с `input` показывается только кнопка «Назад», а
корректный ввод автоматически переводит на следующий шаг. На шаге с `final`
введённое значение сохраняется в статистике и прибавляется к балансу.

## Схема базы данных

- **users** — пользователи: `telegram_id`, `username`, флаги
  `is_authorized` / `is_banned` / `is_admin`, `balance`, `tabla_count`.
- **transactions** — история операций: сумма, баланс после, тип, комментарий, время.
- **resources** — элементы списка ресурсов по пользователям.
- **active_process** — состояние текущего процесса (шаг, время старта,
  выбранный ресурс, результат, прибыль).
- **processes** — завершённые процессы: тайминги, длительность, прибыль,
  результат — основа для статистики.
- **settings** — служебные настройки, в т.ч. хэш пароля доступа.

Пароль хранится в виде SHA-256-хэша, в открытом виде не сохраняется.

## Примечания по поведению

- Кнопка **«Табла»** возвращает в меню, увеличивает счётчик и **прерывает**
  текущий процесс — прерванные процессы в статистику завершённых не попадают.
- На первом шаге кнопка «Назад» отменяет процесс и возвращает в меню.
- Время процесса считается от первого шага до завершения последнего и
  усредняется по всем завершённым процессам.
